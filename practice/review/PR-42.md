## Description

During last week's incident the runbook wiki timed out and `/ask` returned a 500 to everyone. This PR:

1. **Degrades gracefully.** If a source fails, `/ask` still answers, with empty results, and logs a warning
   instead of erroring.
2. **Simplifies the handler.** The two sources are awaited one after the other, which is easier to read and
   to step through in a debugger.
3. **Caches search results.** During an incident the same questions get asked again and again, so `search`
   memoises its results by query.
4. **Removes an arbitrary cap** on `limit`, so the UI can ask for as many hits as it wants.

All small, all low risk. Looks good to merge?
